# 以后怎么避免：这轮问题的根因、规则和自动检查

这一轮（全站 UI/UX、模型 A–D、车里自拍、3D 实测）修掉的问题，归成 6 类根因。每类给出：例子 → 以后的规则 → 能加的自动检查。

## 1. 页面上写的和程序实际做的不一致

**例子**
- 设置页把 fal.ai 标成「可选」，可默认首帧 Seedream 就走 fal。
- 产品资料页写「成片 Logo 用原文件合成」，实际是首帧 AI 画、视频里字变了才贴回。
- 车里自拍草稿显示「脸在画面右边」，真正出图时程序会删掉这句，用户看到的和发出去的不一样。
- 第二段价格按 Sunburst 算（$1.16），实际默认 Seedream（约 $0.89）。
- 页面写「拖蓝球改姿势」，实际按住球拖动转的是视角。

**规则**
- 提示文字只描述代码里真有的行为；改了行为，同一次提交里改文字。
- 价格、供应商、Key 是否必填，只从一个常量（`src/lib/shorts.ts` 的报价、设置页的 Key 表）读，不在文案里手写数字。
- 给用户看的草稿 = 实际发出去的提示词。清理规则（左右位置、衣服、产品）在 AI 返回时做一次，草稿和出图共用。

**自动检查**
- 单元测试：草稿清理后再进出图函数，结果不变（已加 `cleanCarDraft` 测试）。
- 单元测试：每个 Hook 的价格文案用报价常量算，和 `videoUsdPerSec` 对得上。
- 搜索检查：文案里出现 `$数字` 的地方必须来自常量（lint 规则或 grep 脚本）。

## 2. 花钱前没先做免费检查

**例子**
- 卖点空着点「生成剧本」，先弹「约 $0.01，继续？」，确认后才报缺字段。

**规则**
- 所有花钱按钮的顺序固定：免费校验（必填、状态、Key、余额） → 报价确认 → 调用。
- 校验不过时按钮旁边直接写「先填：xxx」，不弹付费确认。

**自动检查**
- 每个付费动作的服务端函数开头调用同一个 `precheck()`；测试里用空输入调用，断言没有产生任务、没有扣预算。

## 3. 状态多了，页面只按一种状态写提示

**例子**
- 3D 页把「已采用」也说成「已确认」，还给了一个点了没用的「退回构图并编辑」。
- 自拍镜头整条视频的声音开关显示没开，旁边又说自拍强制开。

**规则**
- 每个锁定提示都要写：现在是什么状态 → 为什么不能改 → 去哪里改（带按钮或链接）。
- 按钮只在当前状态能成功时出现；不能点的按钮写明原因，不出现「点了没反应」。

**自动检查**
- 给镜头的每个 `stage`（draft / frame_ok / video_ready / accepted）各做一份测试数据，截图走一遍 3D 页和工作台，确认每种状态的提示和按钮都对。

## 4. 只看截图，没真点

**例子**
- 找不到页面时点「回项目中心」不跳转（截图看着正常）。
- 拖手脚、视角钻到地底下、保存后选中的人丢了，只有真拖才发现。
- 调机位滑块时，视窗里的相机框和检查提示都不跟着变。

**规则**
- UI 改动完成的标准：真点过主按钮、真拖过、刷新后看改动还在。只看截图的要在报告里写「没点过」。
- 拖、转、缩放这类交互，要在至少一条有人、一条没人的镜头上各试一次。

**自动检查**
- Playwright 冒烟脚本（不花钱）：打开 3D 页 → 选人 → 换姿势 → 拖手 → 调机位 → 保存 → 刷新 → 断言数据库里的 `layout` 变了。
- 404、空数据、手机 500 像素宽各跑一遍。

## 5. AI 不照要求写

**例子**
- 提示里写了「不要写脸在哪一边」，AI 照样写。
- AI 按「已经组装好」写台词，可产品到手还要自己装，台词就是假的。

**规则**
- AI 输出一律当成不可信：重要限制靠程序清理或校验，不靠提示词。
- Hook 的选项（比如「已经组装好」）要和产品资料对得上，不符合的选项不让选。

**自动检查**
- AI 返回后跑规则检查（左右位置、衣服、产品入镜、Logo 字母），不过就自动修或标红，并在草稿上写出改了什么。
- 台词里出现产品资料没有的卖点时标黄，让用户确认。

## 6. 布局没在真实屏幕宽度上看

**例子**
- 1280 宽时 3D 视窗只剩 300 多像素，工具条压在「+ −」上。
- 往下滚动时「问 AI 大脑」盖住「保存」。
- 手机上写「在右边新建」，表单其实在下面。
- 打开右边的「AI 大脑」栏后，3D 页和模型审核页还按整个浏览器宽度排成多栏，中间的 3D 画面被挤成一窄条，说明文字变成竖排。

**规则**
- 每个页面在 1280、1440 和 500 像素宽各看一次；sticky 元素要互相让开。
- 文案不写「左边 / 右边」这种依赖布局的方位，改写按钮名字。
- 多栏布局按页面实际剩下的宽度排（容器查询 `@container/main`），不按浏览器宽度（`xl:`、`lg:`），因为侧栏、AI 大脑栏会占掉宽度。

**自动检查**
- 截图脚本按三种宽度、AI 大脑栏开和关各出一次图，检查横向滚动条（`scrollWidth > clientWidth`）和元素重叠。

## 每次提交前的清单

1. 文字和行为一致吗？价格、供应商是从常量读的吗？
2. 花钱按钮前有免费校验吗？
3. 每种状态的提示都写了「为什么、去哪里改」吗？
4. 真点、真拖、刷新过吗？
5. AI 输出有程序兜底吗？
6. 1280 / 500 宽看过吗？
7. `npm run lint`、`npx tsc --noEmit -p .`、`npm test`、`npm run build` 都过了吗？
