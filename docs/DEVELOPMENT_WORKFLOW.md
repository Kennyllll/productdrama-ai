# ProductDrama AI — GPT-6 / Devin Desktop 交接流程

## 角色
- 产品负责人（用户）：决定目标与优先级、测试网页、批准合并和新任务。
- GPT-6（ChatGPT）：依据用户反馈制定 PRD、原型逻辑、逐任务技术要求与验收标准；根据 Devin 的结果和代码/截图进行复核。无法自动读取未提供的本地文件，也不能直接遥控 Devin。
- Devin Local：读取当前项目的规则与任务，修改本地文件，运行测试，提交真实执行记录。

## 每次任务的固定循环
1. GPT-6 提供 `tasks/NNN-*.md` 任务卡：目标、范围、输入输出、约束、验收标准。
2. 用户将任务卡加入本地项目 `tasks/`，在 Devin Desktop 打开同一项目文件夹。
3. 给 Devin Local 指令：先阅读 `PROJECT_BRIEF.md`、`AGENTS.md`、对应任务卡，先汇报计划，然后只实现当前任务。
4. Devin 执行，运行 `npm run lint`, `npm run build`，启动 `npm run dev`，给出文件变更、实际测试结果和截图。
5. 用户在 localhost 测试，验收不通过则在 ChatGPT 发送页面截图/报错/变更摘要，生成修复任务。
6. 用户验收通过后，在本地 Git 记录版本，按需求进入下一任务。

## 非常重要的边界
- Devin Desktop 本地工程和 ChatGPT 是两个独立工作环境，默认不自动同步文件和对话。
- 用户复制任务卡、上传相关代码文件或粘贴错误/截图是最简单的交接方式。
- 不使用公开 Github/Vercel 等服务，除非用户明确决定后续上线。
- 后续接真实视频模型 API 时，必须先显示预算、严格限制重试次数，并避免泄露密钥。
